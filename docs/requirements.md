# 要件定義（要約）

クライアントと合意した要件定義書の要約。判断に迷ったらこの文書を優先する。

## 目的

- 公式LINEで消えてしまうやり取り、紙の契約、スタッフの記憶に頼っていたNG情報を一か所にまとめる
- NGの本人だけでなく、その家族（同じ世帯）からの問い合わせにも気づけるようにする
- スマホから検索・登録できるようにする

基本の流れ: 問い合わせが来たら、まず検索 → 該当がなければ新規登録。

## 利用者と規模

- スタッフ 5名程度
- 成約 月50件前後、問い合わせ 月150件前後（年間 約1,800件の登録を想定）
- 主にスマホのブラウザ。PCでも使えること

## 今回やること

- 画面4つ: ログイン（Cloudflare Access が担当）、検索、新規登録、詳細（＋編集）
- 里親顧客とブリーダーの登録・検索・編集
- NG（ブラックリスト）の登録・解除と、理由・経緯の記録
- 新規登録時の自動照合と警告（本人および同じ世帯の可能性がある人）
- やり取りメモの記録（LINE・Instagram・電話の要点を手入力）
- 登録・更新したスタッフと日時の自動記録

## 今回やらないこと

- 公式LINE・Instagram との自動連携
- 動物（個体）の管理、譲渡後のフォロー管理
- 契約書のデータ化、写真やファイルの保存
- 既存データの一括移行（NG対象者は運用開始前に手入力してもらう）
- 細かな権限設定（管理者かどうかの区別のみ）

## NG理由の区分

| 対象 | 区分 |
| --- | --- |
| 里親 | 虚偽申告 / 飼育環境が不適切 / 過去のトラブル / その他 |
| ブリーダー | 健康診断の未実施 / 書類不備 / 説明と異なる状態での引き渡し / その他 |

詳細は自由記述。事実のみを書く運用（画面に注意書きを出す）。

## 照合ルール

| 照合キー | 判定 | 表示 |
| --- | --- | --- |
| 電話番号（数字のみで完全一致） | NG本人の可能性が高い | NG（赤） |
| 住所（番地まで一致） | 同じ世帯の可能性 | 要確認（オレンジ） |
| 苗字＋市区町村 | 家族の可能性 | 要確認（オレンジ） |

警告は保存を止めない。スタッフが理由を確認したうえで「確認して保存」できる。

## 追加要件：ペットフードのサブスク管理（2026年11月追加）

当初の範囲に追加。ペットフードを定期提供（サブスク）している里親を管理する。

- **管理番号**: サブスクごとに自動で付ける（`00001` 形式、5桁ゼロ埋め）
- **オン／オフ**: 一時的に止める（オフ＝休止）・再開する（オン）を何度でも切り替えられる。番号は変わらない
- **終了**: 終了したサブスクは元に戻せない。**その番号は二度と使わない**。再開するときは新しい番号で開始する
- **メニュー**: ペットフードのメニュー（名前・価格・説明）を追加・編集できる。削除はせず「販売停止」にする
- 1つのサブスクに複数のメニュー（数量つき）を入れられる。途中で追加・外すことができ、外した記録は残る
- サブスクは里親の詳細画面から開始する（ブリーダーは対象外）

今回やらないこと（サブスク）: 決済・請求、配送日の自動計算や配送リストの出力、在庫管理
